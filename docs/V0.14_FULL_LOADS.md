# v0.14: What Remote Production Is For

**Player problem.** Central and remote production make the same beams, and a lone shared hauler favored central. There was little reason to build an outpost bench.

**The decision: remote's purpose is saving hauler time, and output stays the same.** I added no bonus for working remotely. A one-line change to how long trips are loaded made that saving large enough to matter. Nobody has played it, so I don't know yet if a player will notice.

## The change

`long_trip_load_pct` goes from 50 to 100 in `data/defs.toml`. A carrier now waits for a full load before a long trip, unless less than that is wanted.

Remote production turns 2 Hardwood into 1 beam before the long walk, so full loads of beams are worth far more trips than full loads of hardwood.

## Measured

20 minutes, same spirits and target. Reproduce with `cargo run -p spirit_sim --release --example outpost_report`.

| Hauler tiles walked | v0.13 | v0.14 |
|---|---|---|
| Central | 902 | 902 |
| Remote | 623 | **454** |
| Central, lone shared hauler | 1,153 | 1,070 |
| Remote, lone shared hauler | 1,390 | **1,027** |
| Central, two haulers | 1,632 | 1,599 |
| Remote, two haulers | 1,158 | **943** |

Steady pace, after a warm-up:

| Hauler walking | v0.13 | v0.14 |
|---|---|---|
| Expanded, central | 71% | 70% |
| Expanded, remote | 52% | **46%** |
| Original, remote | 24% | **15%** |

- **A lone shared hauler now favors remote,** narrowly. That reverses the v0.8 and v0.9 result.
- **Job scoring matters more:** the shared hauler walks 37% less with it (1,627 to 1,027), up from 19%.
- **All 60 beams still arrive** in every layout, and steady beam rates are unchanged.

### What it costs

- **Beams arrive later at first:** the first beam home takes 3:01 instead of 2:11 in the plain remote layout.
- **The crossing takes longer to pay back,** 19:05 instead of 15:17, because that first stock comes home later. After 90 minutes it's level: 690 beams with it, 459 without.
- **Normal game:** no real change. The Forest Crossing is still at 1:57:22.

## Tried and removed

I first built a rule letting a bench worker fetch their own materials from a store beside them, so a hauler needn't walk out just to cross the yard.

| Remote, tiles | Half loads | Full loads |
|---|---|---|
| Worker fetches | 951 | 693 |
| Hauler supplies | 623 | **454** |

It did worse in every layout I checked. A hauler that's already out there supplying the bench picks up beams while it's there. The rule also caused a bug: a bench with nobody assigned to it made no beams at all. The tests and the layout report caught that, and I deleted the rule.

## Validation

- `cargo test --workspace`: **387 pass**.
- **One assertion changed:** "a lone shared hauler favours central" is now the other way round, which is the point of this version.
- Four release-only long-run tests pass.
- `cargo clippy --workspace --all-targets` is clean.
- All 16 UI scripts pass. The save format doesn't change.
- The repo has no CI, so all of this ran locally.

## Not verified

- Whether waiting longer for the first beams feels bad.
