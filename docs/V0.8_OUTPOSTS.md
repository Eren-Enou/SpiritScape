# v0.8: The First Remote Outpost

The question for this version: does a remote outpost create satisfying decisions about where spirits gather, where materials are processed, and how resources are transported?

**It creates real logistics decisions, but they're narrower than hoped.** An outpost changes how far your haulers walk. It doesn't produce more beams, because Ironwood regrowth is the limit in every layout measured. Whether that feels satisfying needs a person to play it. Nobody has, and the v0.7 playtest hasn't happened yet either.

No skills, combat, trading or new production chains were added.

## What was built

Old Growth can now hold a working outpost, made of ordinary buildings in a real place on the map.

| Part | How it works |
|---|---|
| **Outpost Storage** | New building, 80 capacity, costs 30 Logs and 15 Planks. Built by a Construction Spirit carrying real materials. No bonus of any kind |
| **Local Workshop** | The existing Workshop, placed at the outpost: 20 Logs, 20 Planks, 6 Structural Beams |
| **Outpost tab (`U`)** | Place, staff and tune the site, and see what a project still needs |
| **Staff outpost** | One instruction: everyone skilled enough goes there. With two or more haulers, one stays with the site |
| **Keep stock** | Haulers leave this much at the store for local use. Gatherers top it up, then stop |
| **Surplus** | Finished goods go home to Main Storage by themselves |

Setting one up from nothing took four instructions in the reference run: place the store, place the Workshop, staff it, set a beam target.

## Central against remote production

Each run lasts 20 minutes with nobody touching it, from the same spirits, store and 60-beam target. Reproduce it with:

```bash
cargo run -p spirit_sim --release --example outpost_report
```

| Layout | Target met | Hauler tiles | Hauler walking | Units carried |
|---|---|---|---|---|
| Central: beams made at home | 12:19 | 1,221 | 30% | 206 |
| **Remote: beams made at Old Growth** | 12:20 | **622** | 15% | 180 |
| Remote: bench by the bridge | 12:20 | 912 | 22% | 180 |
| Remote: one gatherer | 12:35 | 956 | 23% | 180 |

All layouts made 60 beams from 120 Hardwood, at the same recipe speed.

With a busy plank line at home as well:

| Haulers | Central tiles | Remote tiles | Better |
|---|---|---|---|
| One, shared | **1,298** | 1,690 | Central |
| Two, one posted to the outpost | 1,790 | **1,225** | Remote |

### What this shows

- **Remote halves the hauler's walking when it has nothing else to do.** Two Hardwood make one beam, so half as much travels the long road. This comes only from the recipe and the map.
- **Placement matters.** The same bench by the bridge costs 47% more walking.
- **A remote site needs its own hauler.** One hauler split between both ends of the map walks further than central production does. That was the opposite of what I predicted, and I've kept the result.
- **Output doesn't change.** Every full-strength layout reaches the target at about 12:20. The nine Ironwood trees are the limit, so an outpost frees hauler time. It doesn't make more beams.

## Construction demand

v0.7 found spirits busy only 11% of the time during training, because targets were met quickly. I didn't force any work to raise that. It's still 11% in a session with nothing being built.

Construction now creates real demand through the existing systems:

- **Finished goods:** a Workshop's 6 beams become part of the beam goal. With a target of 0, the settlement made exactly 6, cutting the Hardwood it needed.
- **Raw materials:** project needs now raise the gatherers' goal.
- **Holding back:** production can't take logs a waiting project needs.
- **Afterwards:** workers go back to standing targets or idle.

| Period | Spirits busy |
|---|---|
| Establishing the outpost | 37% |
| Running, with a target of 30 more beams | 18% |
| A training session with no project (v0.7 and now) | 11% |

So the settlement is busy when there's something to build. Once the goals are met, it goes quiet.

Spirits now report which kind of idle they are:

| State | Meaning |
|---|---|
| Goals met | Everything wanted is done |
| Needs resources | Waiting for materials or regrowth |
| Blocked | Stuck on storage, a full bench or a failed trip |
| Awaiting work | Told to rest, off production, or a builder with no project |

## Logistics changes

| Debt from v0.6 and v0.7 | Now |
|---|---|
| Training support used the first Workshop | You choose a bench, and working at one makes it yours |
| Bench stock and recipe inspection used the first Workshop | Both follow your bench |
| Stations were chosen in id order | Workers take the nearest usable bench |
| Training support only brought Logs | Spirits bring your chosen recipe's material, including Hardwood |
| A kept place applied at every bench | It applies at your bench only |
| "Finish the current project" didn't say which | It names the project |

Haulers now fetch from the nearest storage with stock, not always Main Storage. A hauler can be told to carry for one site, using the existing Spirits tab.

**Guards against wasted trips:**
- A long trip (16 tiles or more) waits for half a load, unless less than that is wanted.
- A free worker won't cross the map for a bench with under 4 batches of material.
- A far bench gets no material while a nearer staffed bench can use it. This fixed a real bug found during measuring: haulers were carrying logs out to Old Growth to make planks there.
- Stores hold back what a local bench needs, so nothing is hauled home only to be carried back.

**Nothing teleports.** Every unit is carried by a spirit, and a test confirms a bench stays empty if nobody can carry to it.

## Changes you might notice

- **Optimized training got faster before any investment:** 267 XP/min in v0.7 is now 420, because haulers can draw from the Field Storage directly. It now beats Relaxed, so I removed "slower than Relaxed until it is" from the game, and changed one v0.7 test assertion to match. That's the only older test changed. `docs/V0.7_GAMEPLAY.md` still shows the old figures as a record of that version.
- **Waiting for materials now logs as "waiting"**, not "blocked".
- **Empty hands at a store** take whatever is there when there's nothing to make.

## Saves

- The format is now **version 4**. It adds only fields with safe defaults, and new definitions after the old ones, so no migration was needed.
- **v0.7 saves load**, including one taken mid-session, whose session carries on. `tests/fixtures/v3_*.save` were written by the unmodified v0.7 code.
- **v0.5 and v0.6 saves still load**, and an upgraded save's original is kept beside it.
- **Tested across a save:** a running outpost at three points, construction at Old Growth, instructions and local stock, and training at the remote bench. Each continues identically to a world that was never saved.
- There's no offline production and no passive XP. Tests confirm spirits and an idle player earn nothing at the outpost.

## Architecture

- `outpost.rs` is new: site reports, staffing, local stock, worker states and project needs. It moves no resources and changes no rates.
- `production.rs` gained `supply_source`, `benches_for_input`, `surplus_at` and `held_at`, which all multi-facility decisions go through.
- `Building.keep`, `Spirit.trips` and `TrainingSupport.bench` are new saved fields.
- Scenarios can now start with buildings already standing, and with spirits already posted.

## Validation

- `cargo test --workspace`: **275 tests pass**, 219 from before plus 56 in `tests/outposts.rs`. One older assertion changed, as described above.
- `cargo clippy --workspace --all-targets` is clean.
- **Eleven UI scripts pass** on the final build, including new `ui_outpost.txt` and `ui_remote.txt`. `ui_outpost.txt` places both buildings on the map, staffs the site, then saves and reloads.

## Limitations

- **Outposts don't raise output.** This is the biggest gap against the goal of feeling like an accomplishment. A player sees a freer hauler, not more beams.
- **Measured in development rates only.** Reaching level 10 under normal rules takes about an hour for the reference player, and I haven't run the whole path from a new game to a working outpost.
- **Assignment often barely matters.** A free worker found the outpost bench by itself and matched an assigned one exactly.
- **The UI handles one outpost.** The simulation handles any flagged site, but the tab shows the first.
- **One project at a time**, so the store and Workshop can't be queued.
- **Haulers aren't weighed by distance when choosing between jobs**, only in where they fetch from. That's part of why one shared hauler struggles.

## Technical debt

- A hauler already carrying to your old bench still delivers there, and that stock stays set aside until supply is switched off.
- Training support uses a recipe's first input, which is fine while every recipe has one.
- The Outpost tab's buttons say "Beams", as the Production tab's do.
- The Place Workshop button stays visible after the outpost has one.
- `outpost.rs` has a few `#[doc(hidden)]` helpers that exist only for tests.

## Recommendations for v0.9

1. **Run both playtests first.** v0.7's and this one are still unanswered, and they should set the priorities.
2. **Give Hardwood a reason to matter more.** If beams had uses beyond Workshops, hauler time would be worth more.
3. **Add something only an outpost can do**, if geography alone doesn't feel rewarding. It should come from location, not from a bonus.
4. **Weigh distance in hauler job choice**, so a shared hauler batches work at each end.
5. **Measure the whole road to an outpost under normal rules.**

## Human playtest

```bash
cargo run --release -- --scenario outpost_establishment
```

```bash
cargo run --release -- --scenario remote_production
```

```bash
cargo run --release -- --scenario central_production
```

Press `U` for the Outpost tab, `C` for the whole map and `F6` to write a play report.

**Setting it up**
- [ ] Could you work out where to build without help?
- [ ] Was it clear what the Workshop needed, and who was making it?
- [ ] Did it feel like an accomplishment when it opened?

**Running it**
- [ ] Could you leave it alone for ten minutes?
- [ ] Did you ever have to fix something you hadn't changed?
- [ ] Could you tell why a spirit was idle? Were the four kinds clear?

**The decision**
- [ ] Run Central and Remote side by side. Could you see a difference?
- [ ] Did you care about hauler walking, or only about beams?
- [ ] Did giving the outpost its own hauler feel like a real choice?
- [ ] Would you build one in a real game, knowing it doesn't make more beams?

**Training there**
- [ ] Press **Train here** and work the remote bench. Did support arrive?
- [ ] Did it feel different from training at home?

**Overall**
- [ ] Did expanding feel like it improved your world?
- [ ] What did you want the outpost to do that it couldn't?
