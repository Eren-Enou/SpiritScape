# v0.17: Long Runs

**Question.** Does a game slow down, or its save grow, as hours go by?

**No.** After the guided route, I left a world running for 24 more game hours. Speed and save size stayed flat, so nothing needed fixing. This version adds the measurement and a small wording cleanup.

## Measured

Timings depend on the machine, so compare them with each other. Reproduce with:

```bash
cargo run -p spirit_sim --release --example long_run_report
```

| Game time | Ticks/s | Save size | Save | Load | Events kept | Projects |
|---|---|---|---|---|---|---|
| 02:28 | 18,734 | 89 KB | 0 ms | 1 ms | 200 | 13 |
| 08:28 | 25,365 | 90 KB | 0 ms | 1 ms | 200 | 13 |
| 14:28 | 25,448 | 90 KB | 0 ms | 1 ms | 200 | 13 |
| 20:28 | 24,723 | 90 KB | 0 ms | 1 ms | 200 | 13 |
| 26:28 | 25,750 | 90 KB | 0 ms | 1 ms | 200 | 13 |

The game needs 10 ticks a second, so the simulation has about 2,500 times the speed it needs at 1x, and over 300 times at 8x. Resources still balance at the end.

**What this doesn't cover:**

- **A quiet settlement.** Nobody is playing, so spirits mostly rest. A busy world will be slower, though the guided route itself ran at about the same speed.
- **Rendering.** This measures the simulation only. I haven't measured frame rate, including the extra plank meshes for roads.
- **The finished-project list** grows by one per building, but building counts are capped.

## Wording

Gathering text that assumed trees now fits outcrops too.

| Where | Before | After |
|---|---|---|
| Bench button | Next tree: AUTO | Next target: AUTO |
| Waiting | Waiting for trees to regrow | Waiting for it to recover |
| Toggling | When a tree is finished... | When one is finished... |
| Unlock text | 5 Logs a tree | 5 Logs each |

The play report and a few status lines still say "trees". A test checks the report's wording, and it's not misleading enough to change that test now.

## Validation

- `cargo test --workspace`: **412 pass**. One assertion changed, to match the new waiting text.
- Five release-only long-run tests pass.
- `cargo clippy --workspace --all-targets` is clean.
- All 18 UI scripts pass, with `ui_skilling.txt` updated for the new button name.
- The save format doesn't change.
- The repo has no CI, so all of this ran locally.

## Not verified
