# v0.37: Playing styles

**Player problem.** Every long run so far played one way: it ignored visitors, and did nothing about winter. So nobody knew whether either of those mattered, and the visitors who remember your answer had never been met in a whole game.

**The reference game can now be played six ways, and the results changed what I believed.** These are automated players, so they measure the economy, not how the game feels.

## Design

`play_all_goals_styled` takes a `Style`:

- **Offers:** ignore visitors, take every offer it has the goods for, or turn everyone down.
- **Plans for winter:** keeps a third of the store in logs through autumn and winter.
- **Stocks logs all year:** the same stock, all year. This is the control for planning.
- **No winter:** winter stops nothing. Nobody can play this way. It only measures what winter costs.

The default style does nothing, so every earlier number still means what it did.

## Measured

| Style | All goals | Hearth lit | Visitors | Offers taken |
|---|---|---|---|---|
| Ignores visitors (the default) | 17:01:27 | 13:39:28 | 10 | 0 |
| Takes every offer | 16:59:14 | 13:36:28 | 10 | 6 |
| Turns everyone down | 17:01:27 | 13:39:28 | 11 | 0 |
| Plans for winter | 15:54:51 | 12:46:15 | 9 | 0 |
| Stocks logs all year | 15:34:16 | 12:17:25 | 9 | 0 |
| No winter (control) | 13:29:36 | 10:51:01 | 9 | 0 |

The visitor count depends partly on when each game ends, so don't read much into small differences in it.

```bash
cargo run -p spirit_sim --release --example styles_report
```

### What this shows

- **Winter is expensive.** It costs the reference game about 3½ hours of 17, or about a fifth.
- **Planning for winter isn't what helps.** I first thought it was. The control beat it: keeping logs all year saves 1:27, and keeping them only for winter saves 1:07. So the gain comes from holding more logs. The default reference player simply keeps too few.
- **That's still most of the gain from half the holding.** The winter planner gets about three quarters of the saving while holding the logs for half the year. I can't say from one run of each whether that's meaningful.
- **Offers barely change anything.** Taking all six saves about 2 minutes. They read as choices, but in the economy they hardly register. This is a real weakness in "a choice with a cost".
- **Turning everyone down costs exactly nothing,** as it should. It plays out identically to ignoring them.
- **The returning visitors work in a whole game.** Taking offers brings the pedlar back, and refusing brings the surveyor's son.

## Bugs this found

- **A real deadlock, in the game.** Planks set aside at the bench for your own training were counted as stock. Workers saw their target as met and stopped, while the project couldn't touch those planks. The Forest Crossing sat 3 planks short for hours. A person training on panels could hit the same thing. Set-aside stock no longer counts.
- **That bug was costing the default game 29 minutes.** The Hearth moved from 14:08 to 13:39 once it was fixed.
- **A mistake in the reference player.** With a full bag of Stone it checked for room for logs, and stood idle for 60 hours. A person would just walk over, so this only affected the reference player.

## Validation

- `cargo test --workspace`: **553 pass**, 552 from before plus 1 new, for the deadlock.
- **Eight release-only long-run tests pass,** up from six: taking offers and turning everyone down both play a whole game.
- `cargo clippy --workspace --all-targets` is clean.
- **Thirty-four UI scripts pass.**
- The save format stays at 9.
- The repo has no CI, so all of this ran locally.

## Not verified

- **One run of each style.** The simulation is deterministic, but a small change can move these times by minutes. Treat a 2-minute difference as nothing, and an hour as real.
- Whether a person feels winter the way these numbers suggest.
- Whether offers should matter more. Perhaps being remembered is enough of a reward.

**What would count as failure:** a style that can't finish, or a change to the default style's numbers without a reason.
