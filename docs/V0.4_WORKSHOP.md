# v0.4: The first workshop

This milestone tests one question: *is it satisfying to personally master a
skill, transfer that competency into a permanent spirit, and watch that spirit
contribute to a physical production economy that improves the world?*

It adds a complete Woodcutting -> Woodworking -> Construction chain. It builds
on v0.3 (`v0.3-sustainable-gathering`, PR #1), which wasn't merged when this
work started, so the branch is stacked on it.

## How to try it

```bash
cargo run --release -- --scenario workshop_manual
```

```bash
cargo run --release -- --scenario workshop_automated --production
```

```bash
cargo run --release -- --scenario workshop_construction --production
```

The **Workshop A / B / C** buttons switch between them in game. `P` opens the
Production tab.

| Scenario | What to do | What to look for |

## What was added

| Area | Change |
|---|---|
| Woodworking | A second trainable skill, using the same XP table, history and unlock messages as Woodcutting. |
| Recipes (`[[recipes]]`) | Data-driven: skill, station, level, inputs, output, time, XP. **Rough Planks** (level 1): 2 logs -> 1 plank. **Precise Planks** (level 5): 3 logs -> 2 planks. Workers always use the best recipe their level and materials allow. |
| `Craft` task | One task for the player and spirits. It repeats until materials, room or demand run out. Inputs are taken only when a batch finishes, so an interrupted batch costs nothing. |
| Workshop | A physical building with two buffers: up to 20 raw logs, and up to 20 finished planks. Spirits leave planks there; the player keeps them in their bag. |
| Soul Separation | No crafting-specific code. The preview now also lists recipes lost and recipes the spirit can make, and the panel has a skill picker. |
| Multi-resource logistics | Logs and planks are distinct everywhere. New hauler jobs: `supply` (Main Storage to Workshop) and `collect` (Workshop to Main Storage). Trips reserve stock with the existing `Storage` reservations and release them if the trip fails. |
| Without a hauler | A Woodworking Spirit fetches its own logs and carries its own planks. Slower, but the chain never deadlocks. |
| `ProductionOrder` | Plank target, log reserve, on/off. See "How demand flows". |
| Storehouse | Ordered by the player (`Command::RequestBuilding`, not the planner). Costs 20 planks and 10 logs, goes up near Main Storage through the existing project system, and adds 150 capacity. Up to three. |
| Production tab (`P`) | What limits planks, workshop status, stock bars, measured output, controls, and time use by group. |
| Instructions | Plank target, log reserve, production on/off and per-spirit assignment. Blocked and idle spirits show why in the Spirits card. |
| Map | Workshop shed, Storehouse, plank stacks beside buildings, pink "sawing" status, and hover text listing recipes and whether you qualify. |
| UI scripts | `press <label>`, `tile x y` and `expect <text>`. A failed script now exits non-zero, so scripts work as automated UI tests. |

## How demand flows

Demand moves backwards one step at a time, and every step is bounded.

1. `production_goal` = plank target + planks that active projects haven't reserved yet.
2. `production_deficit` = goal - planks counted toward it (Main Storage, finished at the Workshop, or being carried). It's zero when production is off or nobody is assigned, so an unstaffed bench requests nothing.
3. **Haulers** bring only what the deficit needs, up to the input buffer, counting logs already there or on their way, and only from above the log reserve.
4. **Gatherers** work toward `gather_goal` = max(log objective, reserve) + upstream demand. Upstream demand is capped at `upstream_cap` (40), so a huge target can't ask for everything.
5. When the goal is met, all of these fall to zero and the chain stops.

There's no recursion: one order, one station, one step upstream. Materials only
flow one way (logs in, planks out), so there are no circular requests.

## Measured results

The simulation is deterministic, so these repeat exactly
(`workshop_playtest`).

| Scenario | Result |
|---|---|
| A: 300 XP to level 6 by hand | 37 s, 17 planks stored |
| A: separate 400 of 695 XP | You go to level 4; the spirit is level 5 forever |
| A: spirit reaches 30 planks | 29 s after the sacrifice |
| B: 30 planks from a start of 30 logs | 77 s; 35 logs harvested, 45 used |
| B: target raised to 120 | 411 s more, about 20 planks/min at the end |
| C: planks reserved for the Storehouse | 47 s |
| C: Storehouse complete, capacity 450 | 69 s |

One level 5 spirit makes about 18-20 planks/min. The Starting Grove sustains
about 28 logs/min, which at 1.5 logs per plank supports about 18 planks/min,
so bench and grove happen to be well matched.

## Validation

- `cargo test -p spirit_sim`: 71 tests pass: 22 simulation, 13 gathering, 31 workshop, 5 unit.
- The 31 new tests in `crates/spirit_sim/tests/workshop.rs` cover every item in the milestone's test list, including the field-storage regression.
- Conservation is now `seeded + harvested + crafted = present + consumed + processed` for every resource, and recipe batches must match the ledger. The tests check it on every tick.
- `cargo clippy --workspace --all-targets` is clean.
- UI scripts pass: `scripts/ui_workshop.txt` and `scripts/ui_smoke.txt`.
- One existing test changed: it counted two buildings, and the map now has a Workshop. It now checks for exactly one Field Storage.

**Not verified:** physical mouse and keyboard input, and a person actually
playing it. Whether any of this is fun is still the open question.

## Technical debt

- **One order, one station.** `ProductionOrder` is a single struct and `station()` returns the first match. A second product or workshop needs a list and a choice between them.
- **Workers share a bench.** Two Woodworking Spirits can saw at one Workshop at once, doubling its output. A real slot limit is missing.
- **Hauling is one trip per job.** A hauler doesn't bring logs in and carry planks back on the same round trip.
- **`objective.resource` means "logs" in several places**, such as what the player takes from storage and the raw material named in reports.
- **Status text says "logs" and "planks" directly** in a few labels, so a new product would need them generalized.
- **Bottlenecks use current state,** not a time window, so the label can flip while the chain is busy.
- **The player's bench rule differs from a spirit's:** the player's planks go to the bag. This is deliberate (OSRS-style), but it's a second output path.
- **Storehouse placement is automatic**, at the nearest suitable tile to Main Storage.

## Questions for playtesting

1. **Is the sacrifice still too cheap?** Level 6 takes 37 seconds by hand. Should Woodworking XP be slower, or the recipes further apart?
2. **Does a spirit feel earned?** A spirit reaches 30 planks in 29 seconds, faster than you did. Is that satisfying or deflating?
3. **Is the Precise Planks gap meaningful?** It saves a quarter of the logs. Does losing it hurt, and does a level 5 spirit feel better than a level 2 one?
4. **Should spirits leave planks at the bench,** or carry them to storage themselves as the player does?
5. **Is a reserve understandable?** Do players see why production stops at it, and does the panel's explanation lead them to change it?
6. **What should the next plank sink be?** One Storehouse uses 20 planks. Once storage isn't tight, what makes more planks worth wanting?
