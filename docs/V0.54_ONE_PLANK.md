# v0.54: One plank

**Player problem.** The Training tab lists what you can make at the bench. In the full-map scenario it read:

> 2 Logs -> 1 Planks
> 3 Planks -> 1 Fitted Panels
> 2 Hardwood Logs -> 1 Structural Beams

Every resource had one name, in the plural, and every amount was the number and then that name. It's a small thing, but it's on the screen where you choose what to make, and it's the kind of slip that makes a game feel unfinished.

**Now one of anything is singular.** Nobody has played it.

## Design

- **Each resource with a plural name has a singular in the data:** `one = "Plank"`. Seven of them do: Logs, Planks, Hardwood Logs, Structural Beams, Fitted Panels, Keystones and Bricks. Stone, Clay, Charcoal, Pitch, Stillwood and Dressed Stone read the same either way, so they need none.
- **Every place that writes an amount goes through one function,** `GameDefs::amount`: recipes, costs, what a spirit was made with, a visitor's offer, the labels over stores on the map.
- **Fractions stay plural:** "0/1 Planks" reads as "0 of 1 Planks", which is fine.

**What would count as failure:** "1 Planks" anywhere, or "2 Plank".

## Measured

A new test runs four busy scenarios (full map, kiln yard, mason's yard and panel workshop) for 400 seconds each. It checks every event, notice and recipe line for "1" followed by a plural name. The test needs the new field, so it can't run on the old code. But the screenshot shows the old recipe lines would have failed it. Now nothing does.

The reference game is unchanged: all 19 goals by 16:57:21, and two runs are identical.

## Validation

- Eight release-only long-run tests pass.
- `cargo clippy --workspace --all-targets -- -D warnings` is clean.
- **All 44 UI scripts pass.**
- The save format is unchanged. Resource definitions only gain a field, so nothing is reordered.
