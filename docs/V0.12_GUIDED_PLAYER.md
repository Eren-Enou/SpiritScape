# v0.12: A Player Who Only Knows What the Game Says

**Player problem.** Through v0.9 and v0.10 the reference player needed storage habits I wrote by hand: stashing planks at the outpost, building racks and keeping fewer logs. That proved the route could be finished, not that the game tells anyone how.

**The measurements say the storage message alone is now enough, but only after fixing a real bug it exposed.** A player using nothing but the message reached the Forest Crossing ten minutes sooner than the hand-written player. It's still a script, so this says what the message offers is sufficient. It doesn't say a person would read it.

## Design

- **One list of fixes:** `storage_fixes()` returns what the player can do, best first. The message is written from that list, and the guided player acts on that list, so it can't be told anything a player isn't.
- **Guided player:** `play_guided` walks the same route to the same goals with no stashing, no racks and no change to the log target. When the message appears it takes the first fix it can do, once a minute at most.
- **Same goals:** the guided player still knows what to build next, because the plan buttons and route come from the script. Only storage knowledge is removed.

**What would count as failure:** the guided player getting stuck, or finishing much later, with no game change able to fix it.

## What it found

The first guided run failed. It stopped at 14,115 XP with 27 planks in the bag, Main Storage at 688 of 750, and no message at all.

- **The bug:** the message only appeared with less than a bag of room free. Main Storage refuses surplus planks earlier than that, to keep room for raw materials. Between the two, the player was stopped with no advice. Any real player training Woodworking would have hit it.
- **The fix:** the message now appears whenever Main Storage won't take what the player is making.
- **A second bug that fix would have caused:** the warning clears when there's room, so it would have repeated every tick in that gap. It now clears only when the shortage has really ended. A test covers it.

## Measured

Reproduce with:

```bash
cargo run -p spirit_sim --release --example guided_report
```

| | Hand-written habits | Message only |
|---|---|---|
| Woodworking level 10 | 1:40:37 | 1:28:53 |
| Forest Crossing | 1:57:22 | 1:46:54 |
| Workshop Annex | 2:04:37 | 1:54:09 |
| All roads laid | 2:18:52 | 2:13:21 |
| Stuck with a full bag | 5:36 | 2:25 |
| Main Storage at the end | 381 of 750 | 398 of 750 |
| Things done because the message offered them | 0 | 14 |

The guided player is faster mostly because the message offers Fitted Panels, which the hand-written player never uses on this route. It reacts within a minute and never hesitates, so a person will be slower.

The hand-written player's times moved by a minute or two from v0.11, because it heeds the same message and the message now appears earlier. The two-hour panel run moved too, to 54,140 XP with Main Storage at 703 of 1,350.

## Validation

- `cargo test --workspace`: **378 pass**, 373 from before plus 5 in `tests/guided.rs`.
- Four release-only long-run tests pass, including the guided route. No existing assertion changed.
- `cargo clippy --workspace --all-targets` is clean.
- All 15 UI scripts pass. There's no new screen.
- The save format doesn't change.
- The repo has no CI, so all of this ran locally.

## Not verified

- **Whether a person reads the message.** It's now long: up to four choices in one paragraph.
- Whether the first choice it lists is the one a person should take.
- Physical mouse and keyboard.

## Technical debt

- The hand-written habits are now pointless, because the guided player does better without them. `play_to_expansion` could become guided, but every earlier report's numbers would move, so I've left it for now.
- The message reads "nearly full" even when the store is 90% full and simply refusing planks.
