# v0.30: Sound and Feedback

**Player problem.** The game was silent, and big moments happened only in text. A level or a finished building looked the same as nothing happening.

**The world now responds.** There are eight original sounds, and a burst of light where something happened. I can't hear any of this, so the sounds are unjudged: I know they load and play without errors, not whether they're pleasant.

## Design

- **All sounds are generated** by `tools/make_sounds.py`, using only Python's standard library. Nothing is borrowed, and the same script gives the same files.
- **Sounds:** a chop, stone cutting, sawing, a soft notice, a level-up phrase, a finished building, a change of season, and a long swell for lighting the Hearth.
- **Sparks:** gold from you at a level-up, and pale blue from a building when it's finished.
- **`M` turns sound off and on.**
- **Read-only:** feedback only watches the simulation, so it can't change a game. Loading a save doesn't set off a burst of sounds.

**What would count as failure:** the game failing without a sound device, or sounds firing on load.

## Validation

- `cargo test --workspace`: **503 pass**, with no change, because this is all in the front end.
- Six release-only long-run tests pass.
- `cargo clippy --workspace --all-targets` is clean.
- **Twenty-eight UI scripts pass,** including new `ui_feedback.txt`, which also checks `M`. The log shows no audio errors.
- I inspected a screenshot of sparks rising from the finished Hearth.
- The save format doesn't change.
- The repo has no CI, so all of this ran locally.

## Not verified

- **How any of it sounds.** Nobody has listened to these. Volumes are guesses.
- A machine with no sound device.
- Physical mouse and keyboard.
