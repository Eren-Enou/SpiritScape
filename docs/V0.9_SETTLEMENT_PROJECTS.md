# v0.9: Purposeful Settlement Expansion

The question for this version: can the player direct a sequence of construction improvements that unlock new capabilities, raise sustainable production and support future progression?

**The measurements say yes, with a large caveat.** The Forest Crossing raises Hardwood output by 40%, and it does so by opening real trees, not by a multiplier. A reference player reached it in a normal game in two hours with nothing granted. But the long game also showed that the economy has no large use for planks, and that surplus is now the main thing limiting a real settlement.

Nobody has played any of this. The v0.7, v0.8 and v0.9 playtests are all outstanding, so whether expansion feels meaningful is still unknown.

No new skills, resources or production chains were added. Full numbers are in [V0.9_REPORT.md](V0.9_REPORT.md).

## What was built

| Part | How it works |
|---|---|
| **Hollow Grove** | Six Ironwood trees east of a new ravine, regrowing like any others |
| **Forest Crossing** | Built from the near bank by a Construction Spirit. When it's finished, two water tiles become a walkable bridge |
| **Construction plan** | Up to 4 buildings waiting in order, in the new Projects tab (`B`) |
| **Plan demand** | Planned buildings add to what production and gatherers aim for |
| **Hauler scoring** | Haulers weigh load, distance and urgency, and pick up nearby goods on the way |
| **Workshop Annex** | One more physical place at a bench, so you can train beside two spirits |

### Resource access

The map grew by 12 columns, east of Old Growth. The grove is really sealed: pathfinding finds no route until the crossing's tiles change, so spirits can't reach it and the player is told what's needed. Spirits posted to Old Growth work the grove too once it opens.

| Crossing cost | Logs | Planks | Beams |
|---|---|---|---|
| Development rates | 30 | 40 | 10 |
| Normal game | 30 | 160 | 40 |

It needs an Outpost Storage first. Everything it costs can be made before it opens, so nothing is circular.

## Measured throughput

30 minutes after a 15-minute warm-up, with a target nothing can reach. Reproduce it with:

```bash
cargo run -p spirit_sim --release --example expansion_report
```

| Settlement | Hardwood/min | Beams home/min | Gatherers waiting | Hauler tiles/min | Hauler walking | Bench in use |
|---|---|---|---|---|---|---|
| A. Original, central | 10.8 | 4.8 | 67% | 84 | 41% | 42% |
| A. Original, remote | 10.8 | 4.8 | 66% | 49 | 24% | 43% |
| B. Expanded, central | 15.0 | 8.2 | 46% | 143 | 71% | 68% |
| C. Expanded, remote | 15.1 | 8.1 | 50% | 106 | 52% | 66% |
| D. Expanded, remote, posted hauler | 15.1 | 8.1 | 50% | 150 | 37% | 66% |
| Original, remote, third gatherer | 10.8 | 4.8 | 77% | 50 | 25% | 44% |
| Expanded, remote, third gatherer, posted hauler | 16.1 | 8.0 | 63% | 191 | 47% | 65% |

Beams home run slightly above half the Hardwood rate because stock built up in the warm-up was still being used. Hardwood per minute is the fairer long-term measure.

### What's actually the constraint

- **Before the crossing, it's regrowth.** 10.8 a minute is exactly what nine trees can give, and a third gatherer adds nothing. It only makes them wait longer.
- **After the crossing, it's mostly still regrowth.** 15.1 of a possible 18 a minute, with gatherers waiting half the time.
- **A third gatherer helps a little only once there's more to cut:** 15.1 to 16.1.
- **Central and remote now make the same beams.** Remote's value is hauler time: 106 tiles a minute against 143.
- **A posted hauler doesn't raise output here.** It lowers the share of time walking, from 52% to 37%, which matters if you have other work for that hauler.

So the settlement does sometimes want trees, sometimes a hauler and sometimes nothing. In these runs it never wanted another bench.

## Construction plan

- **Ordering:** only the front of the list becomes a project. Projects still run one at a time.
- **Reordering:** one place at a time. It's refused if something would go ahead of what it depends on.
- **Cancelling a planned building:** it holds nothing, so nothing is lost.
- **Cancelling a project:** allowed until materials leave storage. Reservations are released and the tile is freed.
- **Refused:** duplicates past a building's limit, a full plan, taken or unbuildable tiles, missing prerequisites.
- **Resuming:** a blocked project picks up by itself when its shortage clears.

### Demand rules

- A planned building's cost adds to the goal of each order, on top of its standing target.
- Raw materials go straight into the gatherers' goal.
- Stock in Main Storage counts toward it, and reserved stock is out of `available`, so nothing is counted twice.
- The Projects tab shows each building's shortage after what earlier projects will claim.
- Production can't take raw materials a project needs.
- When the plan is done, workers return to their standing targets. With a target of 0, a crossing made exactly its 10 beams.
- It's bounded: a plan of at most 4, one recipe step at a time, with the existing cap on upstream demand.

## Hauling

Haulers now compare Collect, Supply and Haul jobs instead of always taking them in that order:

```
score = amount x priority x (3 if urgent) / (walk to pickup + trip + 4)
```

A job is urgent when a project needs the goods, a bench is about to stop, or a posted worker is waiting at an empty bench. Goods within 6 tiles of a pickup ride along on the same trip home. Long trips still wait for half a load.

One hauler sharing a busy plank line with the outpost, 20 minutes, same build with scoring on and off:

| | Tiles | Trips | Walking | Target met |
|---|---|---|---|---|
| Fixed order (v0.8) | 1,710 | 79 | 42% | 12:34 |
| **Scored (v0.9)** | **1,390** | 65 | 34% | 12:19 |

That's 19% less walking and a slightly earlier finish. The first beam arrives 32 seconds later, because the hauler finishes nearby work first. Central production improved too, from 1,221 tiles to 902 with nothing else to do. So **a lone shared hauler still favors central production** (1,153 tiles against 1,390), though by less than v0.8's gap. Remote still wins with a posted hauler (1,158 against 1,632).

## Normal-game route

A reference player from a new game, with nothing granted:

| Step | Time |
|---|---|
| First Woodcutting unlock | 0:05:58 |
| First spirit | 0:10:47 |
| Woodworking Spirit | 0:18:55 |
| First settlement improvement | 0:21:22 |
| Woodcutting level 10 | 0:53:50 |
| Outpost Storage | 0:55:56 |
| Woodworking level 10 | 1:41:30 |
| Outpost Workshop | 1:46:44 |
| **Forest Crossing** | **2:00:02** |
| Workshop Annex | 2:07:55 |

- **Interactions:** about 1 a minute.
- **XP earned:** 25,995 Woodcutting and 18,045 Woodworking. 35,600 went into four spirits.
- **Construction used:** 250 Logs, 565 Planks, 78 Structural Beams.
- **After the crossing, left alone for 15 minutes:** 211 Hardwood and 81 beams home.
- **Player's time:** 36% chopping, 16% sawing, 18% waiting for materials, 5% stuck with a full bag.

This is a lower bound from a player who never hesitates. **Two hours says nothing about whether those hours are enjoyable.**

### What the long route found

The short scenarios hid all of these. Each was a real failure, and each is now fixed and tested unless noted:

| Problem | Fix |
|---|---|
| Three Storehouses walled the builder in beside Main Storage for good | A site can't split the open ground around it |
| About 700 hand-made planks filled Main Storage, so no logs could enter | Unwanted finished goods leave 100 room for what's needed |
| The storage advice said to raise the plank target even when planks were the problem | It now looks at what's filling the store |
| A project needing goods brought into a full store could never start | When storage is tight, the builder starts on what's already there |
| The player's own logs took the room a waiting project needed | While a project waits, their spare logs leave that room |
| A level 5 worker counted as staff for beams, starving the real beam worker | A bench only counts if someone there can make the product |
| The hauler tried the biggest pile, was refused, and ignored the beams beside it | Goods with no room aren't considered |

## Surplus planks are now the main limit

**This is the most important finding of this version, and it's only partly solved.** Reaching Woodworking 10 by hand makes about 700 planks. Nothing uses that many.

- The normal game now charges 160 planks for the crossing and 120 for an Annex, using the existing rule that hand training makes plenty of its product. That's a real use, but together they cover well under half.
- With the room rule, Woodworking stalls short of level 10 unless you stash planks elsewhere and build things. The reference player had to do both.
- The run ended with Main Storage full: 251 Logs, 418 Planks, 81 Beams. Beams will stop coming home soon after that.

I tried keeping room for all running orders too. It made the player stuck in ordinary play and didn't help, so I took it out.

## Using manufactured goods

- **Forest Crossing** uses planks and beams to open resources.
- **Workshop Annex** uses them for a physical place at your bench. Before it, a third worker at a full bench is refused. After it, you can train there without moving a spirit. It makes nobody faster.

## Project visibility

The Projects tab shows each building's stage, cost, why it's useful, what's short, who's on it and why it's stopped. The Settlement card shows what's being built, and a locked site says what opens it. Finished projects stay listed with what they changed.

## Saves

- The format is now **version 5**, with a real migration, because the map is larger.
- **What upgrading does:** moves the world onto the larger map, leaves everything where it was, and adds the grove. New trees aren't resources until cut, so the ledger still balances.
- **Tested on real files:** fixtures from v0.5, v0.6, v0.7 and v0.8 all load, conserve resources and keep running. The v0.8 ones came from the unmodified v0.8 code, including a project half-built. Originals are kept beside upgraded saves.
- **Tested across a save:** a queued plan, a half-claimed project, a cancelled project and an open crossing. Each continues identically to a world that was never saved.
- A builder already walled in by an old save stays walled in. The fix only stops new cases.

## Validation

- `cargo test --workspace`: **327 tests pass**, 275 from before plus 52 in `tests/projects.rs`.
- One more test passes in release only: the full normal route, run with `cargo test --release --test projects -- --ignored`.
- **Two v0.8 assertions changed,** both because behavior improved: central production now walks less than v0.8's test assumed, and a second gatherer no longer changes time to target, because regrowth limits it.
- `cargo clippy --workspace --all-targets` is clean.
- **Thirteen UI scripts pass** on the final build, including new `ui_projects.txt` and `ui_crossing.txt`.

## Not verified

- Physical mouse and keyboard.
- **Whether expansion feels meaningful, or whether any of this is fun.**
- How long a person takes, or whether two hours is a good length.
- Whether the storage messages make sense to someone meeting them cold.
- How the wider map feels to move around, and whether the ravine reads as a barrier.

## Technical debt

- Reference-player storage habits (stashing planks, racks, a lower log target) are written into `autoplay` by hand, so it doesn't prove a person would find them.
- Only the first outpost shows in the UI, and the plan always uses the Old Growth tiles it was given.
- The `raw_room` of 100 is tuned for a 750-unit store and is a blunt rule.
- A hauler carrying to a bench you've just left still delivers there.
- `autoplay.rs` is now large, and could be split.
- Screen text says "Beams" in places where it should use the data name.

## Recommendations for v1.0

1. **Run the playtests.** Three versions are now waiting on them.
2. **Give planks a large, ongoing use.** This is the clearest need the measurements show. Without it, a real settlement clogs up within a few hours.
3. **Reconsider what training Woodworking produces,** if a use can't be found.
4. **Decide whether two hours to the crossing feels right** once people have played it.
5. **Make storage problems self-explaining.** The rules work, but there are now several of them.

## Human playtest

Note the time at each step, and press `F6` when you finish.

**A normal game**

```bash
cargo run --release
```

- [ ] How far did you get in an hour? When did you first want to stop?
- [ ] Did a level 10 spirit feel worth the XP?
- [ ] When storage filled up, did you know what to do?

**Opening the crossing**

```bash
cargo run --release -- --scenario forest_access
```

Press `B`, plan the Forest Crossing, then go and chop.

- [ ] Did you understand what it was for before building it?
- [ ] Could you tell why it was waiting?
- [ ] Did it feel like an accomplishment when it opened?
- [ ] Did you walk across to see the grove?

**A queue of projects**

```bash
cargo run --release -- --scenario project_queue
```

Plan an Outpost Storage, the Forest Crossing and a Workshop Annex, then only skill.

- [ ] Could you forget about the plan and trust it?
- [ ] Did you want to reorder anything? Was it clear how?
- [ ] Did the next project feel worth pursuing?

**Central or remote**

```bash
cargo run --release -- --scenario expanded_central
```

```bash
cargo run --release -- --scenario expanded_remote
```

- [ ] Could you see any difference?
- [ ] Which would you build in a real game, and why?

**Hauling**

```bash
cargo run --release -- --scenario shared_hauler
```

- [ ] Does the hauler's route look sensible, or does it seem to dither?
- [ ] Could you tell what it was doing and why?

**Overall**

- [ ] Did spirit labor make sense to you?
- [ ] Did expansion feel like part of the RPG, or like a separate management game?
- [ ] What did you want to build next?
