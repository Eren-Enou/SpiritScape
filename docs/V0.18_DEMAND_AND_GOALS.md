# v0.18: Demand Chains and Goal Messages

**Player problem.** Two gaps left open earlier. A plan needing panels didn't ask for planks, so with none in storage it simply waited. And meeting a long-term goal happened silently.

**Both are closed.** A plan for panels now gets its planks made, and a playthrough says so when a goal is met. Earlier results don't change. Nobody has played it.

## Design

- **Demand chains:** an order's goal now includes what other orders need of it as a material, so wanting 5 panels raises the plank goal by 15. It's capped by the existing `upstream_cap` of 40 and falls back when the panels are done. Recipes can't form a loop, so this always ends.
- **Goal messages:** when a goal is met, a playthrough shows "Ambition met: ...". Each is announced once, checked every 10 seconds.
- **Older saves stay quiet:** the first check only records what's already done, so nobody gets a burst of messages after loading.
- **Scenarios stay quiet too,** because they're for testing one thing.

**What would count as failure:** planks running away past the cap, or a change to any earlier reference result.
