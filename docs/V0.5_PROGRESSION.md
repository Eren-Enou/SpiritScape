# v0.5: From prototype to playable progression

This milestone tests one question: *does training a skill, sacrificing that
progress to create a spirit, and returning to train again feel satisfying when
the settlement supports the next cycle?*

It turns the demonstration scenarios into a game you can start from nothing,
save, close and come back to.

## How to try it

```bash
cargo run --release
```

The title menu offers **Continue** (when there's a save), **New Game** (the
intended pace) and **Fast Game** (rapid testing rates). The old scenarios still
work with `--scenario` and `--demo`.

| Flag | What it does |
|---|---|
| `--new-game` / `--continue` | Skip the menu |
| `--profile normal` or `development` | The pace of a new game |
| `--save-dir DIR` | Keep saves somewhere else |
| `--autosave SECONDS` | Autosave interval; 0 turns it off |

| Key | Action |
|---|---|
| `F5` / `F9` | Save / go back to the last manual save |
| `J` / `T` | Progress tab / Training tab |

`F5` used to restart. A playthrough has no Restart button and no scenario
buttons, so nothing in the panel can throw it away.

## Saving and loading

`spirit_sim::save` owns this, so it's tested without a window.

- **Where:** `%APPDATA%\SpiritScape` on Windows, `~/Library/Application Support/SpiritScape` on macOS, `$XDG_DATA_HOME/SpiritScape` or `~/.local/share/SpiritScape` elsewhere. `SPIRITSCAPE_SAVE_DIR` or `--save-dir` overrides it.
- **What:** the whole simulation state: tick, grid, trees, buildings, spirits with their task queues, player, projects, reservations, production order, training settings, ledger, logs and guidance. Definitions aren't saved; they come from the game's data and the profile named in the save.
- **Format:** a header line (`SPIRITSCAPE-SAVE <version> <checksum>`) and JSON. The checksum is FNV-1a over the JSON.
- **Files:** `world.save` (manual), `autosave.save`, and a `.bak` of each. **Continue** takes the most recent one that works.
- **Atomic replacement:** a save is written to a `.tmp` file, flushed to disk and renamed over the old file, so a crash leaves the old save intact.
- **When:** manually; every 120 seconds of real time in a playthrough (`[saves]` in `data/defs.toml`); on opening the menu; and on closing the window. Scenarios never autosave, so testing can't overwrite a real game.
- **Damage:** a bad header, a wrong checksum, broken JSON, a reference to something that doesn't exist, or a failed conservation check all count as damage. The game reports it, tries the `.bak`, and tells you if it fell back. Nothing panics.
- **Incompatible saves:** another format version, an unknown profile, or definitions that have moved are refused with a reason. Adding new definitions after the existing ones doesn't break old saves. `decode` is where a migration goes when the version changes.
- **Determinism:** after loading, the world continues byte for byte as the original would have. Tests compare the full state text, not a hash.
- **Time away:** nothing is simulated. A loaded world resumes at its saved tick.

## Progression profiles

A profile is a block under `[progression]` in `data/defs.toml`. Nothing else in
the code or data differs between them.

| | Development | Normal |
|---|---|---|
| XP for level 5 | 388 | 1,800 |
| XP for level 10 | 1,154 | 16,000 |
| Smallest spirit | 100 XP | 300 XP |
| Storehouse | 20 planks, 10 logs | 80 planks, 40 logs |

`World::from_scenario` still uses development, so every older test and scenario
behaves as before. `World::new_journey(profile)` starts a real game.

**Why these numbers:**

- XP per log and per plank stay the same, because they're what the player sees on every action. Only the table moves, which is one list to reason about.
- Level 2 stays at about 20 seconds so a new player is rewarded almost at once. Gaps then grow every level: 120, 260, 520, 900, 1,800, 2,200.
- Level 5 is the only tier so far. It's set at about 6 minutes so that Oak feels earned without the first session being all Woodcutting.
- The Storehouse costs 4x in normal because training a skill by hand makes a lot of its product. At the old price, hand-made planks paid for it before a spirit was ever needed.
- The table stops at level 20. There's nothing to unlock above level 5 yet, so finalizing more would be guesswork.

## Soul Separation

The ritual's rules haven't changed. The panel now shows:

- **A comparison** of up to five amounts, chosen from what matters: the smallest spirit, the least that gives the spirit each tier, the most that keeps each thing you can do, and everything.
- **For each:** XP given, your level after, the spirit's level, and whether you lose something.
- **For the settlement:** an estimate such as "Cuts about 25 logs/min from Tree while chopping".
- **The cost:** "This can't be undone. Earning it back takes N XP of your own work."

**Separate Soul** now takes two presses. The second reads "Confirm: give up N XP
forever", and pressing anything else cancels it.

## Spirit-supported training

Spirits carry things. The player does everything that earns XP. Settings are in
the Training tab (`T`) and live in `TrainingSupport`.

**Woodcutting.** Choose a site as your training area and spirits stay out of it.
Then build a **Training Cache** there (15 logs, built by the Construction
Spirit). Drop your logs in it instead of walking to Main Storage. With **Collect
my logs** on, a Hauling Spirit empties it when a load is waiting.

**Woodworking.** With **Stock the bench** on, a Hauling Spirit keeps up to 20 logs
at the Workshop, set aside for you with the existing `Storage` reservations.
Production can't use them. Your planks stay at the bench for the hauler to take
to Main Storage, so you can stand there and saw. Turning this off hands the logs
back to production.

**Rules:**

- Supply only takes logs above the production reserve, and never reserved stock.
- A trip needs a full `haul_min` load, so a trickle doesn't tie up a hauler.
- **Haulers: production first** is the default: support runs after production work. **Haulers: my training first** moves it above. This is two job rules in the hauler's data, not new logic.
- Shortages remain: with no spare logs nothing arrives, and the tab says why.

Reserving the Starting Grove has a real cost. It's the only place with Trees, so
a spirit below level 5 has nowhere left to gather, and the game says so. A level
5 spirit crosses the river to the Oaks, on a much longer trip. That's what makes
a level 5 sacrifice worth more than a level 4 one.

"Selecting the relevant resource" has no control yet, because logs are the only
input in the game.

## New-game guidance

`journey.rs` watches the world and shows one goal in the **What's next** card. It
blocks nothing and rewards nothing. Stages done early are skipped.

| Phase | Goal | Ends when |
|---|---|---|
| A | Reach Woodcutting level 3 | Reached, or a spirit exists |
| B | Create a Woodcutting Spirit | One exists |
| C | Train Woodworking to level 5 | Reached, or a spirit exists |
| D | Create a Woodworking Spirit | One exists |
| E | Build a Storehouse | One is finished |
| F | Regain a sacrificed level | A sacrificed skill is back at its best |

The hint changes with what you're doing, for example "Your bag is full. Click
Main Storage to deposit your logs."

Short messages appear over the map for levels, unlocks, new spirits, finished
buildings, new goals and the first collection. The Progress tab (`J`) shows
levels against your best, XP invested, what each spirit can do, what can be
built and what's short, and recent milestones.

## Measured results

`autoplay.rs` is a reference player. It uses only commands and waits one second
between actions. It never hesitates or reads anything, so **these are lower
bounds, not predictions of a person's times.** The numbers repeat exactly:

```bash
cargo run -p spirit_sim --release --example pacing
```

| Milestone | Development | Normal |
|---|---|---|
| First level | 00:16 | 00:21 |
| First Woodcutting unlock (Oak) | 01:13 | 05:42 |
| First spirit | 01:27 | 10:24 |
| First Woodworking unlock | 02:20 | 14:02 |
| Woodworking Spirit | 02:31 | 17:05 |
| First settlement improvement | 03:29 | 19:05 |
| Sacrificed level regained | 04:03 | 21:58 |

Whole normal cycle: 54% chopping, 26% sawing, 14% walking, 3% idle.

Regaining the 1,800 XP sacrificed, starting from the same moment in normal:

| | Time | Clicks | Storage trips | You walked | You stood idle |
|---|---|---|---|---|---|
| Woodcutting, alone | 04:38 | 38 | 5 | 18% | 2% |
| Woodcutting, supported | 04:32 | 43 | 9 (short ones) | 12% | 6% |
| Woodworking, alone | 05:43 | 61 | 28 | 24% | 3% |
| Woodworking, supported | 08:38 | 13 | 0 | 0% | 69% |

Spirits were idle 54-83% of the time during these runs, because stock targets
were met. Those figures include the Construction Spirit, which has no work then.

**What this shows:**

- **Intentional time:** chopping and sawing are 80% of the cycle.
- **Woodcutting support barely saves time:** 2% faster. Walking falls by a third, but the grove is only 9 tiles from Main Storage. It should matter more far from home, but that isn't measured. The reference player also sacrifices at 3,600 XP, so it keeps Oak; a player who loses Oak has a harder way back than this shows.
- **Woodworking support trades time for attention.** It takes 79% fewer clicks and no trips, but 51% longer, because one Woodcutting Spirit can't keep up with a player who saws faster than it gathers. Alone, the player chops their own logs instead. Those 69% idle are waiting, which may be restful or may be obstructive. Only a person can say.
- **Hand training produces plenty:** a Woodworking Spirit made its first plank in the development run, but in the normal run hand-made planks had already met the target, so it had made none when the Storehouse finished.

## Long-term decisions

These come from existing rules, with nothing added to force them:

| Decision | What pulls each way |
|---|---|
| Sacrifice now, or train to Oak? | A spirit now gathers sooner, but below level 5 it competes with you in the grove |
| Level 5 spirit or keep Oak? | Below 3,600 XP you can't have both |
| Second Woodcutting Spirit? | More logs and bench supply, but more retraining |
| Reserve the grove? | Trees for you, longer trips or a stranded spirit for the settlement |
| Haulers: production or training? | One hauler can't do both at once |
| Planks or logs? | The reserve and the target pull on the same logs |

## Not verified without a person

- Physical mouse and keyboard input: everything was scripted.
- Whether the guidance reads clearly, or anything feels good.
- How long a person takes, and whether waiting at the bench is relaxing.
- Saves across a real crash. The interrupted-write case is tested by simulating what a crash leaves behind.

## Known design weaknesses

- **Only one tier per skill.** Levels 6 and up give only small speed gains, so there's little reason to train on after level 5 except to sacrifice more.
- **Main Storage can stall solo Woodcutting.** With no spending, 300 logs fills it around level 6, and a full bag stops XP. Sawing or a Storehouse fixes it, but the game doesn't explain that.
- **Hand training makes the first Woodworking Spirit look idle.** Planks made while training can meet the target for a long time.
- **Trees stop on depletion.** You click every tree, about 8 clicks a minute. That may suit the game or may tire people.
- **The Training Cache is weak near home**, for the reason measured above.
- **A few logs can sit in the cache** below a hauler's minimum load until you add more.
- **A new game overwrites the old save** the first time it saves, after one warning and one backup. There's only one world.
- **The panel is tall.** The Soul Separation card pushes tabs down, so some buttons need scrolling.
- **`Bot` is a steady player, not an average one.** It can't show how the game feels.

## Recommendations for v0.6

1. **Playtest this first.** The checklist below will show whether the loop works before more is built on it.
2. **Add a third tier per skill, around level 10.** It's the most direct fix for the empty levels above 5.
3. **Give planks a use beyond storage**, so production stays interesting after the Storehouses.
4. **Make training far from home worthwhile**, which would give the Training Cache its purpose.
5. **Consider a "keep working" option at the bench and at trees**, depending on what playtesters say about clicking.

## Human playtest checklist

Start with `cargo run --release` and **New Game**, and note the time at each step.

**First minutes**
- [ ] Did you know what to do first without reading anything else?
- [ ] Did the first level arrive soon enough?
- [ ] Did you find depositing logs without help?

**First sacrifice**
- [ ] Did you understand what you'd lose before pressing the button?
- [ ] Did the comparison help you choose? Which option did you pick, and why?
- [ ] Did it feel like a real cost? Did the spirit feel worth it?

**Woodworking**
- [ ] Was it clear how to get logs to the bench?
- [ ] Did it feel different from Woodcutting?
- [ ] Did you want to sacrifice it, or keep it?

**The settlement**
- [ ] Could you tell why production stopped or slowed?
- [ ] Did the Storehouse feel earned?
- [ ] Did the settlement feel like yours?

**Coming back**
- [ ] Did you find the Training tab?
- [ ] Was retraining better than the first time? How?
- [ ] Was waiting at the bench relaxing, or annoying?
- [ ] Was your settlement's progress worth your lower level?

**Saving**
- [ ] Close the window mid-job and press **Continue**. Was everything as you left it?
- [ ] Did anything duplicate or disappear?

**Overall**
- [ ] How long did you play? When did you first want to stop?
- [ ] Which clicks felt like chores?
- [ ] Would you come back tomorrow?
