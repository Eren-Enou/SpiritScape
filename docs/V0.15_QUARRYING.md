# v0.15: Quarrying

**Player problem.** The game has two skills and one kind of place to work. With the wood economy now having goals and uses, it was time for a second thing to gather. It had to be worth something, not just another number.

**Quarrying works end to end: cut stone, make a spirit, build a second river crossing.** It uses the same rules as Woodcutting, and nearly all of it is data. Nobody has played it. This version also records that physical input is still unverified.

## Design

- **Quarrying:** a new trainable skill, open from level 1, with its own XP and Soul Separation.
- **South Quarry:** six Stone Outcrops south of home. They're worked down and recover like trees.
- **Stone:** a raw resource.
- **Quarrying Spirit:** made by Soul Separation. It only works when Stone is wanted, because Stone has no standing target.
- **Stone Causeway:** 60 Stone and 20 Logs. It opens a second way across the river, straight to the Distant Forest.

Like the Forest Crossing, the causeway adds a real route and no multiplier. Stone isn't a hand-trained product, so its cost is the same in both profiles.

### Rejected

- **A stone recipe or new bench:** Stone needs one good use first. A second chain can follow if people like the first.
- **A standing Stone target:** nothing uses Stone regularly yet.

## Measured

Reproduce with:

```bash
cargo run -p spirit_sim --release --example quarry_report
```

| Player's walk, Main Storage to the Distant Forest | Seconds |
|---|---|
| By the bridge | 16.2 |
| By the causeway | 9.0 |

| Causeway finished, from the start of `quarry_start` | Time |
|---|---|
| Left to the spirit alone | 6:31 |
| With the player cutting too | 6:20 |

- **The walk is 44% shorter,** which matters most for Oak gathered by hand or carried home.
- **Helping barely speeds it up,** by 11 seconds. I first set outcrops to recover in 180 seconds, and helping made no difference at all, so I halved that. Six outcrops are still the limit, and the player cuts from the same ones. That may feel bad, and it's on the playtest list.

**What would count as failure:** woodcutters touching stone, stone demand not stopping, or older saves losing anything. None happened.

## What the checks caught

- **Definition order:** I first put the causeway in the middle of the building list. The save check refused every older file, which is what it's for. It's now last.
- **A missing visual field** crashed the game on launch. Only the UI script could catch this, because the simulation never reads that file.

## Saves

- The format is now **version 8**. The map gained the quarry, so older saves go through `migrate_map` again. Nothing already on the map moves, and no tree is doubled.
- **Tested on real files:** a fixture from the unmodified v0.14 code, plus v0.5 to v0.10 fixtures.

## Physical input

**Still unverified.** I asked for computer control of the game and the request was declined, or it timed out, so I recorded that and moved on. I didn't try another way of sending input. The scripted input goes through the game's own input handling, but skips the operating system and window layer.

## Validation

- `cargo test --workspace`: **401 pass**, 387 from before plus 14 in `tests/quarrying.rs`. No existing assertion changed.
- Four release-only long-run tests pass.
- `cargo clippy --workspace --all-targets` is clean.
- **Seventeen UI scripts pass,** including new `ui_quarry.txt`.
- I inspected screenshots of the skill panel, the quarry and the opened causeway.
- The repo has no CI, so all of this ran locally.

## Not verified

- Physical mouse and keyboard.
- **Whether Quarrying is worth training, or whether the causeway is worth 60 Stone.**
- Clicking an outcrop in the game window. The script's click on tile (4, 22) didn't start cutting, because that tile is off screen from the start. Cutting is tested in the simulation.
- How the normal game fits this in: the reference route doesn't use Quarrying yet.

## Technical debt

- A resting Quarrying Spirit shows "objective satisfied (60/20 Logs)", which is about the wrong resource.
- Some text still says "trees" where it means anything gatherable, including "wait for trees" and "Next tree".
- `Tree` in the code now also means an outcrop.
